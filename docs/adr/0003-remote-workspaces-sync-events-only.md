# Workspaces remotos versionam apenas eventos, nunca o estado derivado

Cogitamos deixar o git rastrear tanto `events.log` quanto os arquivos derivados (`tasks/*.md`, `boards/*.md`) de um workspace remoto, mas isso reintroduziria exatamente o problema que o mdwal existe para resolver: dois peers editando o mesmo arquivo de task concorrentemente produziriam um diff de merge do git sobre YAML frontmatter, sem noção de LWW por campo. Decidimos que as pastas fixas de entidade (`tasks/`, `boards/`, e quaisquer outras introduzidas por migração, ex. `lists/`) ficam no `.gitignore` de todo workspace remoto — só `events.log` é versionado. O conteúdo do `.gitignore` é derivado do conjunto atual de pastas fixas do schema, não uma lista hardcoded: toda migração que cria/renomeia/remove uma pasta fixa regenera o `.gitignore` como efeito colateral estrutural da própria migração (mesmo mecanismo de "operação de pasta", sem precisar de log próprio). O estado local (`tasks/*.md`, `boards/*.md`, etc.) é sempre reconstruído via replay determinístico do log, nunca commitado diretamente.

A branch `master` do `manager` é a única exceção a essa regra: como nunca é editada diretamente por um usuário (só é reescrita de forma determinística pelo comando `rebuild`), ela não sofre do problema de merge conflict que motiva a regra — por isso é a branch onde os arquivos derivados de fato são commitados, servindo de snapshot de bootstrap para novos peers. Seu `events.log` permanece sempre vazio.
